# bdpwire: the generator decision (spec Part D.3, recorded at P0)

**Decision (2026-09-07, P0):** the Read-profile DTOs are **hand-written Go
types validated against the vendored bundle by tests** — the fallback that
`BDP_GRAPH_CLI_AND_STORAGE_SPEC.md` Part B8 records for exactly this case
("fallback recorded at P0: hand-written DTOs validated against the schema").
No code generator, no new tool or module dependency, no Makefile change: the
drift gate is the test suite in this package, and it already runs inside
`make api-check`.

## The question

At the 2026-09-07 decision, the bundle had 26 `$defs` (JSON Schema
2020-12); it is the normative source. The current Read refresh is recorded
below. The Go types must follow it, and the tree must notice
when they stop. Three ways to get there were on the table:

- **(a)** the house pattern — `internal/httpapi/apigen` is generated by
  `go tool oapi-codegen` from an OpenAPI 3.0 document and `make api-check`
  regenerates and diffs;
- **(b)** a JSON Schema 2020-12 → Go generator run on the bundle directly;
- **(c)** hand-written types, with tests that hold them to the bundle.

The bar, from the task: keep `make api-check` honest, add no external tool
unless clearly justified. Both generators were actually run on the pinned
bundle in a scratch directory; nothing from those runs is committed.

## Evidence

### (a) oapi-codegen over an OpenAPI document

Two ways to reuse it, and neither survives contact:

1. **Put the BDP definitions into `openapi.v0.yaml`.** Ruled out before
   running anything: Part C of the spec freezes `openapi.v0.yaml` and
   `TestSpecRouteParity`, and the legacy surface must stay byte-identical.
2. **A second OpenAPI document whose `components.schemas` `$ref` the vendored
   bundle.** Tried, with a 26-entry wrapper generated from the bundle's
   `$defs`:

   ```text
   $ go tool oapi-codegen -generate types,skip-prune -package bdpwire -o out.go wrapper-3.0.3.json
   error generating code: error generating type definitions: error generating Go types for
   component schemas: error converting Schema AbsoluteHttpUrl to Go type: error turning
   reference (./bdp-v0.schema.json#/$defs/absoluteHttpUrl) into a Go type: unrecognized
   external reference './bdp-v0.schema.json'; please provide the known import for this
   reference using option --import-mapping
   ```

   The 3.1.0 wrapper fails the same way and first prints `WARNING: You are
   using an OpenAPI 3.1.x specification, which is not yet supported by
   oapi-codegen`. `--import-mapping` maps an external file to an
   already-generated Go package; it does not read the file. Making (a) work
   therefore means transcribing the bundle's `$defs` into an OpenAPI 3.0
   `components.schemas` copy — a second, hand-maintained spelling of the
   schema, which is exactly the drift the pin exists to prevent — and even
   then the OpenAPI 3.0 schema dialect has no `const`, no `if`/`then`/`else`,
   no boolean property schemas (`archivedAt: false`) and no `propertyNames`,
   so the conditional problem table and the closed-versus-open posture would
   be dropped silently, and `make api-check` would be certifying the copy
   rather than the pin.

### (b) A JSON Schema 2020-12 → Go generator

`github.com/atombender/go-jsonschema` v0.24.1 (the maintained line of
omissis/go-jsonschema; the latest release at evaluation), run directly on
the bundle:

```text
$ go run github.com/atombender/go-jsonschema@v0.24.1 -p bdpwire \
    --schema-package=<$id>=bdpwire --schema-output=<$id>=out.go bdp-v0.schema.json
```

It generates (1090 lines; the output needs only the standard library) and
loses precisely the parts that carry protocol meaning:

| Bundle construct | Generated |
| --- | --- |
| `reference` — `oneOf` URI string / pinned object | `type Reference interface{}` |
| `bdpVersion` (`const "0"`), `readDiscovery.profile` (`const "read"`) | `interface{}` |
| collection `next` — `oneOf` URL / null | `Next interface{}` |
| `readProblem.allOf[*].if/then` — code → type/status/retry, `archivedAt` gating | dropped: no table, no `archivedAt` member |
| `additionalProperties: false` on every closed envelope | not enforced: the generated `UnmarshalJSON` checks required members and `minLength`, then passes unknown members through `json.Unmarshal` silently — which also matches names case-insensitively and maps null onto the zero value (P0 council findings 3 and 4), so the closed shape needs a decoder of its own either way |
| `ownsOutgoing` `propertyNames`, `uniqueItems` | dropped (harmless) |

Every row above would need a hand-written wrapper anyway — a sum type for
references, a nullable continuation, the problem table, the constants — so
the generator would own the easy two thirds and hand code would own the third
that matters, with two sources of truth for one envelope. It would also add a
`tool` directive and its module graph (goccy/go-yaml, sanity-io/litter,
sosodev/duration, mitchellh/go-wordwrap) to go.mod/go.sum for a 22 KB
schema. Not clearly justified.

### (c) Hand-written types, validated against the bundle

What this package is. The bundle stays the only source of truth; the
generator's contract is turned into a gate instead:

- `pin_test.go` — every vendored file's sha256 and git blob sha1 recomputed
  from the bytes on disk; every file under `schema/` listed and every listing
  present; the `commit:` and `schema-id:` headers equal to the Go constants;
  the embedded bundle equal to the file.
- `schema_parity_test.go` — every `$defs` entry bound to a Go declaration,
  two-way. Per object definition: member bijection with the struct's JSON
  tags (conditional-branch members included), required ⇔ no `omitempty`,
  closed ⇔ no extension carrier (and the one open envelope has exactly
  one), and each member's Go type against its `$ref` or inline shape,
  recursively (the limits groups, the two maps, the arrays, the nullable
  `next`). Every shared and inline enum, and both constants, two-way. The
  problem table derived from the bundle's conditionals equal to
  `readProblemTable`, and the `status` enum equal to that table's image.
  Zero values marshal every required member and no optional one.
- `roundtrip_test.go` — strict decode → marshal → canonical compare over
  every envelope-shaped document in the vendored fixtures and the spec's own
  examples, with a coverage floor per type; the spec's Read+Update and
  Transactional discovery examples refused by the Read type.
- `decode_test.go` — the strict/open posture, the Reference sum, `next:
  null`, never-null arrays and properties, extension members, the table.
- `strict_test.go` — the decoder's own contract (`decode.go`, P0 council):
  exact, case-sensitive member names and no duplicates; null refused
  wherever the bundle gives no null; required members present; each
  member's JSON type; integers decoded exactly from any RFC 8259 spelling
  (`1.0`, `1e0`, `100e-2`) within the documented int range; the two
  discovery constants through `ReadDiscovery.Validate`; the encoding/json
  entry points of `Reference` and `ReadProblem` held to the same rule.
- `matrix_test.go` — the pinned Read matrix validates responses only against
  definitions bound here; its problem expectations agree with the table; its
  discovery pointers resolve through `ReadDiscovery`; it and its catalog name
  the same scenarios.
- `imports_test.go` — standard library only.

`make api-check`'s second step is `go test ./internal/httpapi/... -count=1`,
which includes this package, so the PR-policy gate that guards the OpenAPI
contract runs all of the above with no Makefile edit.

## Re-pinning

1. Change the commit in `schema.go` (`Pin`) and in `schema/PROVENANCE` (`commit:`).
2. Re-fetch every verbatim file `PROVENANCE` lists from that commit, byte-identical
   (`gh api -H "Accept: application/vnd.github.raw"
   "repos/gastownhall/bdp/contents/<upstream path>?ref=<commit>"`), fetch
   `docs/specs/bdp.md` at that commit the same way, record its
   `git hash-object` as the `spec-blob:` header, and re-extract the spec
   examples (each PROVENANCE entry names its fence's line range, opener
   through closer; renumber the ranges and the file names if the spec moved).
   Run `BDP_SPEC_AT_PIN=<path to the fetched spec> go test
   ./internal/httpapi/bdpwire/ -run TestDerivedEntriesReproduceFromTheSpec`
   to prove the derived entries against the file, offline.
3. Recompute the digests in `PROVENANCE` (`shasum -a 256`; `git hash-object`).
4. `go test ./internal/httpapi/bdpwire/...`. Every failure is a real change at
   the new pin: a new definition (bind it in `defsToGo`, write the type), a
   new or removed member, a changed vocabulary, a changed problem row, a
   fixture that stopped exercising a shape. Fix the types to the bundle —
   never the tests to the types.

## What would flip the decision

A generator that turns 2020-12 conditionals and `oneOf` sums into Go a
discriminated union and the problem table survive, or a later-profile bundle
large enough that hand-maintaining it costs more than a generator plus the
wrappers it would still need. Either way the tests in this package stay: they
are the contract, whoever writes the types.

## On the spec's `make bdp-gen` / `make bdp-check`

Part B8 sketches those targets for the generated case. Under (c) there is
nothing to regenerate, and `bdp-check` is exactly
`go test ./internal/httpapi/bdpwire/...`, which `make api-check` already
runs. If the names are wanted in `scripts/ci/pr-policy.sh` for readability
they are one-line aliases; this slice does not add them, because it stays
inside the package by design.

## Read foundation refresh — 2026-09-10

The current pin is `19923f5bb6cc3f4ee4c508e36df3bd4c5c52344b`, the merged
Read foundation. The earlier generator experiment above is dated evidence;
the current bundle has 27 definitions, including `ownedWildcardDeclaration`.
`OwnedOutgoingDeclarations` separates its max-only wildcard from explicit
`OwnedLinkDeclaration` values. Strict decoding and marshaling enforce the
cross-entry explicit-max bound as well as the local shapes. The named
`resource-erased` pointer exclusion applies by presence, while ordinary
RFC 9457 extensions remain open. The catalog and matrix now have 46 rows.
These are vendored contracts and local DTO checks, not 46 served observations
or a Read capability claim. No later-profile bundle or evidence seal is copied.
